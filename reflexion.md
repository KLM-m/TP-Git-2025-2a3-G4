1. Structure actuelle du projet Git après toutes les opérations
La structure finale du projet est désormais centrée sur une branche main propre et linéaire, rendue possible grâce à l'utilisation du Squash & Merge lors de la fusion de la Pull Request finale. Les branches de travail individuelles ont montré une diversité de modèles d'intégration. Elles ont été soit fusionnées via des Merges (avec et sans fast-forward), soit réintégrées via un Rebase (ce qui a réécrit l'historique de l'Élève 3 pour un alignement propre). Les opérations d'historique ont inclus un git revert (ajoutant un nouveau commit d'annulation tout en conservant l'historique) et un git reset --hard (suppression définitive des commits locaux pour la démonstration).

2. Différence entre git fetch et git pull
La distinction principale réside dans leur impact local. git fetch télécharge toutes les données et l'historique distants (origin), mais ne modifie pas le répertoire de travail local ni la branche courante. C'est la méthode à privilégier pour vérifier le travail des collaborateurs sans risquer de conflit immédiat. En revanche, git pull est un raccourci pour git fetch suivi immédiatement d'un git merge (ou rebase). Il met à jour directement la branche locale et ne doit être utilisé que lorsque l'on est prêt à intégrer les modifications et à résoudre d'éventuels conflits.

3. Différence entre git reset et git revert
Ces deux commandes permettent d'annuler des changements, mais leur nature et leur impact sur l'historique sont opposés. git revert est la méthode la plus sûre : elle crée un nouveau commit d'annulation qui défait les changements du commit ciblé, conservant ainsi l'historique intact. À l'inverse, git reset déplace le pointeur de la branche (HEAD) et, avec l'option --hard, réécrit l'histoire en supprimant les commits. L'utilisation de git reset --hard sur une branche qui a déjà été partagée sur le serveur est très risquée. Elle crée des incohérences pour les collaborateurs, car elle supprime des commits qu'ils pourraient avoir déjà basés sur leur propre travail. C'est pourquoi, en environnement collaboratif, git revert est systématiquement l'outil à utiliser pour annuler des changements publics.
